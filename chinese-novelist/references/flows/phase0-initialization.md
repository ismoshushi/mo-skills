# 第0步：初始化与偏好加载

**每次触发SKILL时首先执行：**

## 1. 读取用户偏好

检查 `user-preferences.json` 是否存在
- 存在 → 加载偏好数据，用于后续选项排序、推荐标记、个性化欢迎语
- 不存在 → 使用默认值，首次交互结束后自动创建

偏好数据结构与更新规则详见 → [shared-infrastructure.md](shared-infrastructure.md)

## 2. 快捷入口检测

分析用户的首次输入是否已包含丰富的创作信息（题材、主角、冲突等关键要素）

- 如果用户说"接着写/继续" → 直接走第 4 节中断续写检测
- 如果用户说"我有大纲/已经写了XX章/接着我的写" → 走 [phase0-import.md](phase0-import.md) 已有大纲接入流程
- 如果信息充足 → 展示提取结果，提供三个选项：
  - "是的，直接开始规划" → 跳过问答，进入第二阶段
  - "先展示提取的信息让我确认/修改" → 展示配置供确认后进入规划
  - "不，我还是想走一遍问答流程" → 进入第一层问答
- 如果信息不足 → 直接进入第一层问答

## 3. 个性化欢迎

（如有偏好数据）：

> "欢迎回来！基于你之前的创作习惯，我为你做了一些推荐（标记为⭐的选项）。"

## 4. 中断续写检测（针对 issue #3/#22：写一半断了、清屏后接不上）

扫描 `./chinese-novelist/` 目录下的项目文件夹。
**不要只信 `02-写作计划.json` 里的 status**（中断时它可能是 stale 的），
以磁盘上的实际章节文件为准：

1. 列出所有 `第XX章-*.md` 文件，取最大章节号 `N`
2. 检查 `02-写作计划.json`：
   - 如果有章节 `status` 是 `in_progress` 但磁盘上没有对应文件
     → 视为中断残留，状态改回 `planned`，从该章重新开始
   - 如果 JSON 缺失或损坏 → 根据磁盘文件重建（`第01..N章` 标 completed）
3. 下一章 = `N+1`（以实际文件为准，不以 JSON 为准）
4. 续写前必须读：上一章结尾（最后 500 字）+ `04-术语表.md` + `03-文风基准.md`

如果找到未完成项目：
  - 展示项目信息：小说名称、完成进度（N/Y 章已完成，依据实际文件）
  - 提供选项：
    - "继续上次创作" → 进入第三阶段，从第 N+1 章继续
    - "开始新作品" → 进入第一层问答
- 如果未找到 → 正常进入快捷入口检测或第一层问答
